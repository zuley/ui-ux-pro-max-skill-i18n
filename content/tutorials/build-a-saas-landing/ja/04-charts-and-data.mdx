ステップ 02–03 の Hero は確定した。次はその下のセクション——フィーチャー
グリッド、そしてこのシリーズで初めて登場する**データ**だ。ここで新しい
失敗モードが現れる。紫のグラデーションより質が悪い。訪問者がその場で
指摘できるからだ：モデルは**数字をでっち上げる**。

AI に SaaS のランディングページを頼むと、フォールドの下のどこかに
「10,000+ の満足した顧客」「99.9% のアップタイム」、そして軸ラベルの
ない右肩上がりの折れ線が現れる。どれも事実ではない。モデルは嘘をついて
いるわけではない——「ランディングページとはこういうもの」をパターン
補完しているだけだ。だがそれを公開すれば、嘘をつくのは*あなた*になる。

このステップのルール：**ページ上のすべての数字はあなたから来る。
さもなければ存在しない。**

## まず実在する素材を集める

ステップ 01 と同じく、作業はプロンプト入力欄の外から始まる。生成の前に
書き出しておくものは 3 つ：

<Checklist
  storageKey="saas-landing-step-04-material"
  title="グリッドのプロンプトを書く前に"
  items={[
    { id: 'features', label: '機能を 3〜6 個、それぞれ平易な一文で（それが何か、ではなくユーザーに何をするか）' },
    { id: 'metric', label: '顧客に「出典は？」と聞かれて答えられる実在の指標を 1 つ' },
    { id: 'shape', label: 'その指標の形：単一の数字か、時系列のトレンドか、比較か？' },
    { id: 'none', label: '正直チェック：実在の指標がまだ無いなら、チャート無しで出すと決める' }
  ]}
/>

最後の項目は慰めではない。明快な機能文 6 つで**チャート無し**のページ
のほうが、捏造グラフ付きのページより信頼できる読み味になる。初期の
プロダクトに見栄えのする数字は普通ない。あるふりをするのは、データ版の
AI slop だ。

## そのチャートは紙面に値するか

チャートが正当化されるのは、指標が言葉では運べない**形**を持つときだけだ：

- **単一の数字**（「インポートの中央値は 40 秒」）は大きな stat 表示に
  ——大きな文字とひとこと文脈。チャートではない。
- **トレンド**（「処理時間が 6 リリース連続で短縮」）は小さな折れ線。
- **比較**（「同じファイルでうちのパーサー vs 既存 2 社」）は横棒 3 本。

<Callout tone="warn" title="チャート slop にも署名がある">
  ほぼ等分の 5 切れ円グラフ、3D の棒、軸のないグラデーション塗り
  エリアチャート、メッセージが「右肩上がり」しかないグラフ——これらは
  データ界の紫グラデーションだ。「このチャートを消したら、読み手の判断の
  何が変わる？」に耐えられないなら、消す。
</Callout>

## プロンプトの拡張——同じ骨格にブロックを 1 つ足す

プロンプトはステップ 02 のテンプレートに `# Data` ブロックを 1 つ
足しただけだ。モデルにはこれを逐語的な原資料として扱わせる。Hero は
ステップ 03 の Keep フェンスが守る。

<CodeBlock
  title="フィーチャーグリッド + チャートのプロンプト"
  language="text"
  code={`app/(marketing)/page.tsx を拡張する。Hero は最終版——1 バイトも
触らない。その直下にセクションを 1 つだけ追加する。

# Decisions（ステップ 01 で確定済み）
Style: <あなたのスタイル名>
Palette: <あなたのパレット名>——チャートはこの色だけを使う。

# Data（逐語的に——捏造・丸め・外挿は禁止）
機能：
1. 5 万行の CSV をインポートし、スキーマを書かずに型付きの列を得る。
2. すべての変換は実データの行でプレビューしてから実行される。
3. 壊れた行は隔離される。黙って捨てられることはない。
4. Postgres、BigQuery、プレーンファイルへワンクリックでエクスポート。
指標（比較）：同じ 5 万行のファイルで、最初のクリーンなテーブルまでの中央値：
- 当社：4 分
- 手書きスクリプト：35 分
- レガシー ETL スイート：初回実行前のセットアップに 90 分

# Task
フィーチャーグリッド（デスクトップ 2x2、モバイル 1 列）を上の 4 文で
作り、指標のチャートを 1 つ：横棒 3 本、実数値のラベル付き。

# Constraints
- チャートはインライン SVG。チャートライブラリ禁止、アニメーション禁止。
- 軸と棒のラベルには # Data の実数値を表示する。
- このセクションに他の数字を一切出さない。証言もロゴ壁も無し。
- アイコンは Lucide、カードに 1 つずつ。絵文字禁止。

# Output
同じファイルに、Hero の下へ新セクションを追加したもの。Hero、その
import、Hero より上のすべてに手を入れない。`}
/>

重みの大半は 2 つの細部が支えている。括弧書きの**「捏造・丸め・外挿は
禁止」**は、「4 分」が「他のどれより 5 倍速い」に化けるルートを塞ぐ。
そして**「他の数字を一切出さない」**は、本物のデータに捏造の隣人を
添える挙動を止める——典型的な事故は、唯一の実在指標が 3 つの捏造指標に
囲まれている、というものだ。

## チャートが間違って返ってきたら

たいてい 1 回は間違う。モデルは凡例とグリッド線、そしてあなたが渡して
いない「業界平均」の 4 本目の棒を愛している。セクションごと作り直すな
——これこそステップ 03 の場面だ。Keep/Change を 1 ラウンド：

<CodeBlock
  title="チャートへの外科手術的フォローアップ"
  language="text"
  code={`このセクションはチャート以外は正しい。フィーチャーグリッドは
そのまま維持する。

# Change（これだけ）
凡例と「業界平均」の棒を削除——私のデータに存在しない。各値ラベルは
対応する棒の端に置く。他は何も変えない。`}
/>

ここで守るべき直感は、このシリーズ全体が鍛えているものと同じだ。
**モデルが提案し、あなたのデータが裁く。** あなたの文で組んだグリッドと
あなたの数字で描いたチャートは、モデルの幻覚よりはるかに説得力がある。
顧客の「誰が言った？」に耐えられるからだ。
