चरण 02–03 का hero अब locked है। उसके नीचे का section आता है—feature grid और पहली बार **data**। यहाँ एक नई failure mode आती है, जो purple gradients से अधिक खराब है क्योंकि visitors आपको पकड़ सकते हैं: मॉडल **numbers गढ़ता है**।

AI से SaaS landing page माँगें तो fold के नीचे कहीं “10,000+ happy customers”, “99.9% uptime” और बिना axis labels का ऊपर-दाएँ जाता line chart मिलेगा। कुछ भी सच नहीं। मॉडल ठीक-ठीक झूठ नहीं बोल रहा—वह landing pages का pattern पूरा कर रहा है। लेकिन इसे ship करेंगे तो झूठ *आपका* होगा।

इस चरण का नियम: **page का हर number आपसे आएगा, वरना दिखाई नहीं देगा।**

अंतिम item consolation prize नहीं। छह स्पष्ट feature sentences और **बिना chart** वाला landing page fabricated graph वाले page से अधिक विश्वसनीय है। Early products के पास आमतौर पर impressive numbers नहीं होते; उलटा दिखावा data वाला AI slop है।

## क्या chart अपनी जगह के योग्य है?

Chart तभी उचित है जब metric का ऐसा **shape** हो जिसे words नहीं दिखा सकते:

- **Single number** (“median import 40 seconds लेता है”) को बड़ा stat चाहिए—large type और context की एक line। Chart नहीं।
- **Trend** (“छह releases में हर बार processing time घटा”) को छोटा line chart चाहिए।
- **Comparison** (“एक ही file पर हमारा parser बनाम दो पुराने competitors”) को तीन horizontal bars चाहिए।

<Callout tone="warn" title="Chart slop की भी अपनी पहचान है">
  पाँच लगभग बराबर slices वाला pie chart, 3D bars, axes के बिना gradient-filled area charts और हर chart जिसका केवल संदेश “ऊपर और दाएँ” है—ये data के purple gradients हैं। यदि “यह chart हटाने पर मेरा decision कैसे बदलेगा?” का उत्तर chart नहीं झेलता, उसे हटा दें।
</Callout>

## Prompt बढ़ाएँ—वही संरचना, एक नया block

Prompt चरण 02 वाला template है, बस एक `# Data` block जुड़ता है जिसे मॉडल verbatim source material माने। चरण 03 का Keep fence नीचे काम करते समय hero बचाता है।

<CodeBlock
  title="Feature grid + chart prompt"
  language="text"
  code={`Extend app/(marketing)/page.tsx. The hero is final — keep it
byte-for-byte untouched. Add ONE section directly under it.

# Decisions (locked in, from step 01)
Style: <your style name>
Palette: <your palette name> — the chart uses ONLY these colours.

# Data (verbatim — do not invent, round, or extrapolate)
Features:
1. Import a 50k-row CSV and get typed columns without writing a schema.
2. Every transform is previewed on real rows before it runs.
3. Broken rows are quarantined, not silently dropped.
4. One-click export to Postgres, BigQuery, or a plain file.
Metric (comparison): median time to first clean table, same 50k-row file:
- Us: 4 min
- Hand-written scripts: 35 min
- Legacy ETL suite: 90 min setup before first run

# Task
A feature grid (2x2 on desktop, single column on mobile) using the four
sentences above, plus one chart for the metric: three horizontal bars,
labelled with the real values.

# Constraints
- Inline SVG for the chart. No chart library, no animations.
- Axis/bar labels must show the actual numbers from # Data.
- No other numbers anywhere in the section. No testimonials, no logos.
- Icons from Lucide, one per feature card. No emojis.

# Output
The same file with the new section added under the hero. Do not modify
the hero, the imports it uses, or anything above it.`}
/>

दो details अधिकतर काम करती हैं। Parenthetical **“do not invent, round, or extrapolate”** वह loophole बंद करता है जिसमें 4 minutes “बाकी सब से 5x faster” बन जाता है। और **“no other numbers anywhere in the section”** मॉडल को real data के पास invented numbers सजाने से रोकता है—classic failure है एक सच्चे metric के चारों ओर तीन झूठे metrics।

## Chart गलत लौटे तो

आमतौर पर एक बार गलत लौटता है। मॉडल legends, gridlines और आपके data में न दिया “industry average” वाला चौथा bar पसंद करता है। पूरा section re-roll न करें—यही चरण 03 वाली स्थिति है। एक Keep/Change round:

<CodeBlock
  title="Chart के लिए surgical follow-up"
  language="text"
  code={`The section is right except the chart. Keep the feature grid
exactly as-is.

# Change (only this)
Remove the legend and the "industry average" bar — it is not in my
data. Put each value label at the end of its bar. Change nothing else.`}
/>

यहाँ बचाने वाला instinct वही है जिसे पूरी series सिखाती है: **मॉडल प्रस्ताव देता है, आपका data निर्णय करता है।** आपके sentences का grid और numbers का एक chart, मॉडल की hallucination से कहीं अधिक convincing हैं—क्योंकि customer के “किसके अनुसार?” सवाल को झेल सकते हैं।
