步骤 02–03 的 Hero 已经锁定。接下来是它下面那一屏——特性网格，以及
这个系列里第一次出现的**数据**。一个新的失败模式在这里登场，它比紫色
渐变更糟，因为访客可以当场戳穿你：模型会**编数字**。

让 AI 写一个 SaaS 落地页，折叠线以下大概率会出现「10,000+ 满意客户」
「99.9% 在线率」，以及一条没有坐标轴、一路向右上的折线。没有一个是真
的。模型并不算撒谎——它只是在模式补全「落地页长什么样」。但如果你把
它发布出去，撒谎的就是*你*。

这一步的规则：**页面上的每一个数字都必须来自你，否则它就不该出现。**

## 先把真实素材凑齐

和步骤 01 一样，活儿从 Prompt 输入框之外开始。生成任何东西之前，先把
三样东西写下来：

<Checklist
  storageKey="saas-landing-step-04-material"
  title="写网格 Prompt 之前"
  items={[
    { id: 'features', label: '三到六个特性，每个用一句大白话描述（它为用户做了什么，而不是它是什么）' },
    { id: 'metric', label: '一个真实指标——客户问「数据哪来的」时你能答上来的那种' },
    { id: 'shape', label: '这个指标的形状：单个数字、随时间的趋势，还是一组对比？' },
    { id: 'none', label: '诚实检查：如果你还没有真实指标，就决定不放图表' }
  ]}
/>

最后一条不是安慰奖。一个有六句清晰特性描述、**没有图表**的落地页，
读起来比一个带着捏造图表的更可信。早期产品通常没有亮眼的数字；假装
有，就是数据版的 AI slop。

## 这张图配得上版面吗？

只有当指标具有文字承载不了的**形状**时，图表才是合理的：

- **单个数字**（「导入中位耗时 40 秒」）适合做成大字 stat——大号字
  体加一行上下文。不是图表。
- **趋势**（「处理耗时连续六个版本下降」）适合一张小折线图。
- **对比**（「同一个文件，我们的解析器 vs 两家老牌产品」）适合三根
  横向条形。

<Callout tone="warn" title="图表 slop 也有自己的签名">
  五块几乎等大的饼图、3D 柱状图、没有坐标轴的渐变填充面积图，以及任
  何唯一信息是「向右上走」的图——这些就是数据界的紫色渐变。如果一张
  图扛不住「把它删掉，我的决策会有什么变化？」这个问题，就删掉它。
</Callout>

## 扩展 Prompt——同样的骨架，多一个块

Prompt 还是步骤 02 的模板，只多一个 `# Data` 块，要求模型把它当成
逐字引用的原始素材。步骤 03 的 Keep 栅栏负责保护 Hero。

<CodeBlock
  title="特性网格 + 图表 Prompt"
  language="text"
  code={`扩展 app/(marketing)/page.tsx。Hero 已定稿——一个字节都不要动。
在它正下方新增一个 section。

# Decisions（已锁定，来自步骤 01）
Style: <你的风格名>
Palette: <你的配色名>——图表只准用这套颜色。

# Data（逐字引用——不许编造、不许四舍五入、不许外推）
特性：
1. 导入 5 万行 CSV，不写 schema 就拿到带类型的列。
2. 每个变换在真实数据行上预览后才执行。
3. 坏行会被隔离，不会被悄悄丢弃。
4. 一键导出到 Postgres、BigQuery 或纯文件。
指标（对比）：同一份 5 万行文件，到第一张干净表的中位耗时：
- 我们：4 分钟
- 手写脚本：35 分钟
- 传统 ETL 套件：跑通前要 90 分钟配置

# Task
一个特性网格（桌面 2x2，移动端单列），用上面四句话；外加一张图表
呈现指标：三根横向条形，标注真实数值。

# Constraints
- 图表用内联 SVG。不引图表库，不加动画。
- 坐标/条形标签必须显示 # Data 里的真实数字。
- 这个 section 里不准出现任何其他数字。不要证言、不要 logo 墙。
- 图标用 Lucide，每张卡一个。不准用 emoji。

# Output
同一个文件，在 Hero 下方加入新 section。不要修改 Hero、它用到的
import，以及它上面的任何内容。`}
/>

两处细节扛了大部分重量。括号里那句**「不许编造、不许四舍五入、不许
外推」**堵住了「4 分钟」变成「比所有对手快 5 倍」的漏洞。而**「不准
出现任何其他数字」**阻止模型给你的真数据配上编造的邻居——经典翻车
现场就是：你唯一的真实指标，被三个捏造的指标簇拥着。

## 图表回来是错的怎么办

通常会错一次。模型酷爱图例、网格线，还有一根你从没提供过的「行业平
均」条。不要重摇整个 section——这正是步骤 03 的场景。来一轮
Keep/Change：

<CodeBlock
  title="针对图表的外科手术式后续"
  language="text"
  code={`这个 section 除了图表都对。特性网格保持原样。

# Change（只改这个）
删掉图例和「行业平均」那根条——我的数据里没有它。把每个数值标签
放到对应条形的末端。其他什么都不要动。`}
/>

这里要捍卫的直觉，和整个系列训练的是同一个：**模型负责提案，你的数
据负责定夺。** 用你的句子搭的网格、用你的数字画的图，比模型幻觉出来
的任何东西都更有说服力——因为它经得起客户问一句「谁说的？」
