上一步结束的时候你手上有张 5 行的便签：受众、感觉、风格、配色、3 个
不要的东西。这一步要把这张便签变成**第一个真正的 Prompt**——产出
落地页 Hero 的那一个。

我们**故意只先做 Hero**。让模型「一次性设计一个落地页」是回到 slop
最快的路。让它只做**一个 section，并且把你已经做好的决定塞进去**，
是离开 slop 最快的路。

## 这一步的产出

一个能截图能用的 Hero。具体说：

- 一个**像是你产品在说话**的标题，不是「让你的工作流焕然一新」
- 一句副标，**一句**——不是三行特性
- **一个**主 CTA（没有第二个「了解更多」）
- 视觉处理和上一步定的「风格 + 配色」一致

就这些。**没有** feature grid、**没有** logo 墙、**没有** 客户证言。
那些是后面几步的事。

## 一个好用的 Prompt 长什么样

每一个能让你「第一版就想留」的 Hero Prompt，结构上大致是**同样 5 段**，
顺序也基本固定。记住这个形状——后面每个 section 你都会复用：

最常见的错误是把「任务」放错了位置。很多人开头就写「给我做个 Hero」，
约束写在后面。模型把**先读到的东西**当作重力中心——所以**先读到**
的应该是「你要它扮演谁」和「哪些决定已经定死了」，**而不是任务本身**。

## 模板直接抄

把下面这个复制走，替换掉 step 01 那 5 行：

<CodeBlock
  title="Hero Prompt 模板"
  language="text"
  code={`你是一位资深产品设计师，正在做一个 SaaS 落地页。这个项目的所有
视觉决定已经被前置做完了，你的工作是**执行**，不是**重新决定**。

# 已锁定决定
受众：<step 01 写的一句话>
2 秒第一印象：<step 01 写的一个形容词>
风格：<从 50 种风格里挑的名字，比如「Editorial Brutalist」>
配色：<从 21 套配色里挑的名字，比如「Slate Ink」>
不要：<step 01 写的 3 件事>

# 任务
做这个落地页的 Hero section。**只有 Hero**——不要 feature grid、
不要 logo 墙、不要客户证言、不要 footer。**一屏装得下**（1440 宽
桌面）。

Hero 包含：
- **1 个标题**（1-2 行，最多 ~10 个词）。这个标题要读起来**像是
  为上面那个受众写的**，不能是泛 SaaS 的腔调。不要「焕然一新」，
  不要「为现代团队打造」。要具体到那个受众。
- **1 句副标**（最多 ~18 个词）。用人话说清楚这是给谁用的、做什么的。
- **1 个**主 CTA（一个按钮）。**没有**第二个「了解更多」。
- 视觉风格符合上面定的「风格 + 配色」。

# 约束
- 严格执行禁止清单。如果模型某个默认选择正好命中禁止项，挑下一个
  最佳替代。
- 标题是这一页**最响**的东西，其他所有东西**让位**。
- **不要渐变背景。不要三栏卡片**（那是后面 section 的事，不是 Hero）。
- 用系统化间距：8px 基线，垂直节奏都是 24px 的整数倍。

# 输出
输出 1 个文件：app/(marketing)/page.tsx
栈：Next.js 15 App Router、React Server Components、Tailwind v4。
**不要 client component**，**不要 Tailwind 以外的依赖**。SVG 内联。`}
/>

这看起来对一个 section 来说 Prompt 有点长。**是有点长。** 原因是：
**Prompt 里每一条，都是你不这样写就会重摇的东西。把决定前置**——
这就是为什么你能一次出一个不重摇的 Hero。

## 好的产出长什么样

跑完这个 Prompt 之后，下面这些应该都能答 **yes**：

  title="第一个 Hero 的验收清单"
  items={[
    { id: 'specific', label: '标题里提到了**这个受众**特有的东西——不是「团队」「工作流」这种泛词' },

    { id: 'palette', label: '主色肉眼看得出是你指定的那套配色' },
    { id: 'style', label: '视觉处理对得上你指定的风格（衬线 vs 无衬线、非对称 vs 居中等）' },
    { id: 'no-slop', label: '你那 3 个禁止项**一个都没有**出现' }

/>

5 条对了 4 条，这版就可以送去 step 03。**如果错了 2 条以上，不要
重摇**——回去看 Prompt 是哪段太泛了。基本上每次都是「已锁定决定」
那一段不够具体。**改一行，重跑**。

<Callout tone="warn" title="不要不改 Prompt 就重摇">
  跑同样的 Prompt 期待这次能出更好的东西——这是用 AI 最贵的失败
  方式。**你不喜欢产出，就改 Prompt。** 产出方向对、某一个维度偏，
  **就改 Prompt 里对应那个维度的那一行**，然后重跑。**不要瞎摇**。
</Callout>

## 为什么这个结构能复用

这个 5 段结构——**角色、决定、任务、约束、输出**——在 step 03–05
里每个 section 都会用同样的形状。一旦你内化了它，写 pricing 区域
的 Prompt、FAQ 区域的 Prompt 都是 3 分钟的事：**决定块保留不动，
换任务和约束，重跑**。

这一步真正在练的技能**不是**「写好 Prompt」，而是**把决定前置，让
Prompt 少干一点活**。
