让模型写一个落地页，你会得到标题 `Inter`、正文 `Inter`。不是因为
Inter 不好——它是一款出色的屏显字体——而是因为它是*统计上最安全*的
答案。而安全恰恰是问题所在：字体是一个页面向外界发出的最快的信号，
说明「这是个什么东西」；Inter 的信号是「这可以是任何东西」。

Skill 内置 50 组精选字体配对，正是因为出路不是「认识更多字体」，
而是有一套**选择的方法**——一套你也可以徒手跑的方法。它就是三个问题。

## 问题一：这个产品的声音是什么？

不是受众——是*声音*。假设产品会说话，替它写一句话：「我精确，还有点
严厉。」「我温暖，带手工感。」「我昂贵，而且安静。」这句话到字体的映射，
比任何人群画像都直接：

- **精确 / 技术** → 标题用怪诞体或几何无衬线（Space Grotesk、
  IBM Plex Sans），常配一个等宽体做点缀。
- **温暖 / 人性** → 人文主义无衬线（Source Sans 3、Nunito Sans），
  或正文用低对比衬线（Source Serif 4）。
- **昂贵 / 杂志感** → 标题用高对比展示衬线（Fraunces、Playfair
  Display），正文压一个克制的无衬线。
- **俏皮 / 消费级** → 圆角端点（Quicksand、Baloo 2）——其余一切都要
  收着，否则整页会滑向玩具感。

如果这句「声音」你写不出来，先停下。这还不是字体问题，是定位问题，
任何配对都救不了。

## 问题二：标题和正文的反差在哪个轴上？

一组配对成立的条件是：两款字体在**恰好一条明显的轴**上不同，其余
全部一致。展示衬线压无衬线正文：*结构*的反差。粗怪诞体压安静的人文
体：*温度*的反差。等宽标题压无衬线正文：*语境*的反差——上面是机器
的声音，下面是人的声音。

配对的失败方式有对称的两种。**太近**（Inter + Roboto）：读者感到一
种说不清的不一致，像两种几乎一样的白色。**太远**（毛笔手写体 + 几何
无衬线）：反差轴一多，页面读起来像两个产品钉在一起。

<Callout tone="info" title="眯眼测试">
  排一个标题加两段正文，退后一步，眯起眼。你应该立刻分得清标题和正
  文（反差存在），同时它们看起来仍像成套买的（一条轴，不是三条）。
</Callout>

## 问题三：正文字体在普通屏幕上扛得住 16px 吗？

展示字体是在 64px 试镜的，正文字体活在 14–16px。正文资格的清单很短：
够大的 x 高度、开放的字怀（`e` 和 `a` 不糊成一团）、真斜体（如果你
需要强调）、表格数字（如果数字对你的产品重要）。Fraunces 是一款华丽
的标题字体，也是一款没法读的正文字体——大多数「失败的配对」，其实
是把展示字体硬按进了正文岗位。

## 把选择编进 Prompt

光给名字活不过和模型的第一次接触——它会加载 Playfair，然后照样用
Inter 排你的按钮，因为你没说不行。先决策，再约束：

<CodeBlock
  title="UI Prompt 里的字体块"
  language="text"
  code={`# Typography（已锁定）
标题：Fraunces，字重 600，紧行距（1.1），只用于 h1/h2。
正文 + UI 控件：Source Sans 3，基准 16px，行距 1.6。
价格表里的数字：表格数字（tabular figures）。
禁止：Inter、Roboto、Open Sans、把 system-ui 当「兜底选择」、
在任何地方出现第三款字体。`}
/>

禁止清单比正向清单更重要。「用 Fraunces」加上沉默，模型的习惯还在；
「任何地方不准出现第三款字体」才是真正改变输出的那一行。

## 我们反复回头用的三组配对

来自 Skill 字体库，附上它们的声音句：

- **Space Grotesk / Source Sans 3**——「我是一把锋利的工具，不是一个
  平台。」开发者工具、数据分析，一切骨子里带终端的东西。
- **Fraunces / Source Sans 3**——「我深思熟虑，还有点书卷气。」编辑型
  产品、高端服务、想表达*品位*的品牌。
- **IBM Plex Sans / IBM Plex Mono（点缀）**——「我是你可以信任的基础
  设施。」金融科技、安全、想要分量但不想穿西装的 B2B。

这三组没有一组是冷门的。这正是重点：赢过「满屏 Inter」的从来不是
猎奇——是有人做了决定，而页面看得出来。
