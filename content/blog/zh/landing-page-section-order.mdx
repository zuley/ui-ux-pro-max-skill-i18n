让模型写落地页，你每次都会拿到同一根脊柱：Hero、三个特性、证言、
价格、页脚 CTA。这个顺序不算错——它是*中位数*顺序，训练数据里所有
落地页的平均值。也就是说，它只对一个不存在的产品最优：中位数产品，
卖给中位数访客。

落地页是一场论证。版块是它的段落，顺序就是论证的结构。而和任何论证
一样，正确的结构取决于一个压倒其余的变量：**读者落地时，已经有多
信这个说法？**

## 决定顺序的那一个问题

排版块之前，先替你最重要的那类访客回答：*他们落地的那一刻，在怀疑
什么？*

常见答案只有三种，每一种产出一张不同的页面：

- **「这问题真有解吗？」**——他们怀疑的是*品类*。开头把问题演活，
  紧跟演示。这是 **show-first（先演示）** 页。
- **「行吧，但对我管用吗？」**——他们怀疑的是*匹配度*。开头放和他们
  长得像的人的证言，再给细节。这是 **proof-first（先证明）** 页。
- **「这品类我熟，凭什么选你？」**——他们怀疑的是*差异*。开头给那条
  竞品说不出口的尖锐主张，再上证据。这是 **wedge-first（先亮刃）** 页。

模型生成的中位数页面三者都不是。它在三种怀疑之间和稀泥，所以读起来
像墙纸。

## 三根脊柱

<CodeBlock
  title="按主导怀疑排版块"
  language="text"
  code={`SHOW-FIRST（新品类，对想法本身缺乏信任）
Hero（讲问题，不讲产品）→ 现场演示/视频 → 工作原理三步
→ 用 FAQ 处理异议 → 单一 CTA
证言：省略或缩到很小。对一个还不相信存在的东西，
没人会信陌生人的夸奖。

PROOF-FIRST（成熟品类，对「你」缺乏信任）
Hero（结果 + 给谁用）→ logo 行 + 一个数字 → 2-3 条具体证言
→ 和证言一一对应的特性 → 价格 → CTA
证言扛起整页；特性只负责*解释*那些夸奖。

WEDGE-FIRST（拥挤品类，比价型访客）
Hero（楔子主张）→ 诚实的对比表 → 把楔子立住的那一个特性，
讲深 → 价格紧贴对比表的推论 → 迁移/换用版块 → CTA
把对比藏起来是经典错误：他们反正会比，
只是不带你的框架去比。`}
/>

注意什么在动：价格。Show-first 页推迟它（信念建立之前谈钱显得僭越）；
wedge-first 页提前它（比价型访客找不到价格就走人）。中位数页面永远
把它放在第四格——一个对谁都不对的位置。

## 版块数量也是论证的一部分

每个版块应该消解一个具体的怀疑。这给了你一把带牙的尺子：给每个版块
写出它回答的那个怀疑，如果两个版块回答的是同一个怀疑，**合并它们**。
生成的页面在这把尺子下常年不及格——「特性」「优势」「工作原理」通常
是同一个段落换了三身衣服。

五到六个版块能消解大多数论证。再多就不是论证了，是拖延议事。

<Callout tone="info" title="略读测试">
  滚动页面，只读各版块的标题。它们应该自己就构成一个完整的论证——
  主张、证据、收束——因为大多数访客实际就是这么读的。如果标题串
  起来是「强大的功能 / 为什么选择我们 / 立即开始」，那这页没有论证，
  只有家具。
</Callout>

## 写进 Prompt 的说法

版块顺序是决策，所以它进决策块——点名版块、给定顺序、各自标注它
消解的怀疑：

<CodeBlock
  title="落地页 Prompt 的结构块"
  language="text"
  code={`# 页面结构（已锁定——不许增、删、调序）
1. Hero——怀疑：「这适用于我的场景吗？」一个主张，一个 CTA。
2. 对比表——怀疑：「这和 X、Y 有什么区别？」
   诚实的行；包含一行我们输的。
3. 深潜——怀疑：「楔子主张是真的吗？」把对比表第一行
   立住的那一个特性。
4. 价格——怀疑：「这点差异值多少钱？」
5. 迁移——怀疑：「换过来疼不疼？」三步，一个 CTA。
不设证言版块：我们还没有可署名的客户，
占位的夸奖读起来就是假的，因为它确实是假的。`}
/>

最后一行最重要。不明说的话，模型会插入带编造人名的证言——而一个
捏造的「Sarah K.，CTO」对信任论证的伤害，超过任何一个缺失的版块。

版块顺序不是落地页上创意住的地方，是*推理*住的地方。定下怀疑、排好
论证，然后让模型去写段落——而不是写逻辑。
