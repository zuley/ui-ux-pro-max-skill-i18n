クロードに「同じページをダークモードにして」と頼むと、技術的には
暗い何かが返ってくる——`bg-gray-900`、`text-gray-300`、アイコンは
どれも少し彩度を落としたバージョン——でも、ページは<strong>背骨を失っている</strong>。
コントラストは平板で、アクセントカラーは泥色だ。全体が
<strong>コスチュームをまとったライトモード</strong>に見える——暗さのために設計された
デザインではなく。

これは AI スロップの中でも最もよくある形であり、原因は明確だ：
モデルがダークモードをライトテーマの<strong>変換</strong>として扱っている。
同じ階層、同じアクセント、同じシャドウのレシピ——それを反転しただけ。
それは良いダークモードではなく、だから毎回こうなる。

## 「ダークモードは独立したデザイン」とはどういう意味か

本物のダークテーマは「ライトテーマだけど `--bg: #1a1a1a`」ではない。
コントラスト、奥行き、アクセントについての<strong>並列の決定セット</strong>だ。
この議論の標準的な形は Material 3 の「サーフェスによる高さ」モデルだ——
サーフェスは手前に来るほど<strong>明るく</strong>なる。なぜなら
黒い背景にシャドウを落とすことはできないから。

AI 生成のダークモードがカードを背景から浮かせるのに `box-shadow` を使っていたら、
それが指紋だ。闇の中にシャドウはない。<strong>光があるだけだ。</strong>

<Callout tone="info" title="これを直すメンタルモデル">
  ライトモードでは、奥行きはシャドウから来る。ダークモードでは、
  奥行きは<strong>明るさ</strong>から来る。暗い背景上の「浮き上がった」
  カードは、その下のサーフェスより<strong>明るい</strong>——
  発光しながら暗いのではなく。
</Callout>

## AI ダークモードであることを示す 4 つの指紋

モデルが返したスクリーンショットをスキャンするとき、この 4 つを探す。
どれも一つひとつが指紋だ：

1. <strong>純粋な黒背景</strong>（`#000` または `#0a0a0a`）。本物のダークテーマは
   `#1a1a1a`～`#1f2937` あたりに座る。なぜなら OLED 純黒は
   隣接するすべての色の命を吸い取るからだ。UI の他の部分に
   ブルーやウォームなトーンがあるなら、背景もそれに合わせるべきだ。

2. <strong>ライトモードのアクセントをそのまま引きずっていること。</strong>
   白背景で映えるインディゴは、暗い背景では<strong>ネイビーの泥</strong>になることが多い。
   ダークモードのアクセントはほぼ常に、ライトモード版より
   <strong>明るく、彩度が低い</strong>必要がある。

3. <strong>本文テキストが `#fff` または `gray-100`。</strong>暗い背景上の純粋な白は
   ビリビリする。本物のプロダクトのダークモードは `gray-200` や
   `rgba(255,255,255,0.87)` のようなものを使い、テキストがページの
   上に<strong>乗る</strong>ようにする——浮いて見えないように。

4. <strong>グレーのティントではなく不透明度で設定されたボーダー。</strong>
   `border-white/10` は AI の指紋だ。機能はするが、
   インターネット上のどのページも同じ見た目になる。
   `rgb(38 43 56)` で設定されたボーダーは、意図的に見える。

## 実際に機能するプロンプトパターン

修正は<strong>「ダークモード版を作って」と頼むのをやめること</strong>だ。
ライト版を一度も見たことがない新しいデザイナーにブリーフィングするかのように、
ダークテーマを注文する：

<CodeBlock
  title="本物のダークテーマのプロンプトたたき台"
  language="text"
  code={`このページのダークテーマをデザインする。ライトテーマを出発点にしない。

背景：#14161a（純粋な黒ではない、ニュートラルウォームなダーク）
サーフェス（カード、パネル）：#1c1f24（bg より明るい——ダークでの
  高さはそうやって機能する）
本文テキスト：rgba(255, 255, 255, 0.86)
ミュートテキスト：rgba(255, 255, 255, 0.56)
アクセント：ライトモードの #4f46e5 インディゴを明度軸上で上方にシフトして
  #818cf8 に。同じ色相、より高い輝度。より青くではなく、より明るく。
ボーダー：rgb(38 43 56)。白に不透明度ではない。
浮き上がった要素に box-shadow は使わない。代わりに明るいサーフェス色を使う。

テーマ全体が「暗さのためにデザインされた」ように見えるべきで、
「ライトから移植された」ように見えてはならない。ライトモードの対応物を
反転したように感じるものがあれば、それを変えること。`}
/>

最後の段落が最も効く。<strong>ライトテーマから乖離する</strong>明示的な許可が、
モデルが機械的な反転をするのを止める。

## どんなダークモードにも使える読み取りテスト

モデルが何か返したら、出荷前にこの 15 秒テストをやる：

<Checklist
  storageKey="blog-dark-mode-test"
  title="15 秒ダークモードチェック"
  items={[
    { id: 'bg', label: '背景は純粋な黒ではないか？（#1a あたり、#000 ではない）' },
    { id: 'accent', label: 'アクセントカラーはライトモード版より明るく見えるか？' },
    { id: 'depth', label: '浮き上がったサーフェスはシャドウではなくページより明るいか？' },
    { id: 'body', label: '本文テキストは純粋な #fff ではなく、わずかにオフホワイトか？' },
    { id: 'border', label: '仕切り線は白に不透明度ではなく、ティントのかかったグレーか？' }
  ]}
/>

5 つのうち 4 つに「はい」と答えられなければ、それはダークモードではなく
AI ダークモードだ。

## 根本的なルール

前の記事の AI スロップを修正したのと同じ原則がここにも当てはまる：
<strong>ダークモードは変換ではなく、決定だ。</strong>色を反転した「同じもの」として
扱った瞬間に、出荷する価値のある良いダークテーマを成立させる
独自の性格をすでに失っている。

モデルは反転を頼めば喜んで反転する。代わりに<strong>デザイン</strong>を頼む——
そしてダークテーマには独自の意見があると伝える。

上のプロンプトを毎回ゼロから書く必要はない。
